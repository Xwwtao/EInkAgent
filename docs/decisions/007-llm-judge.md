# 007 模型裁判与人工校准（P2 第二层）

## 问题

第一层评测用关键词检查回答，暴露了两类盲区（`evals/reports/` 中五次运行）：

- **误判正确回答**：说法不同就失败（"没有公开数据"不含"没有公布"）。第 5 次运行后关键词已冻结，不再逐条补。
- **漏掉无依据的陈述**：t02 曾两次声称"Leaf5+ 是开放系统"，当时该字段为 NULL，关键词检查照样通过。

需要一个能理解语义的检查，但模型裁判本身也会出错，不能直接信任。

## 候选方案

**方案 A：裁判打 1–10 分（相关性、准确性、完整性等多维度）。** 信息量大，但分数难以校准：
人很难稳定地区分 7 分和 8 分，也就无法验证裁判是否可靠。

**方案 B：裁判只回答两个是/否问题，并用人工标注校准。** 每个问题人也能稳定判断，
可以统计裁判与人的一致率，以及裁判漏掉了多少人工认定的问题。

## 选择：方案 B

## 两个问题

1. **grounded**：回答中关于设备的每一条事实陈述（规格、价格、能否做某事），是否都能在工具结果中找到依据？
   工具结果里为空（NULL）的字段被断言为有或没有，算无依据。裁判同时列出它认为无依据的句子。
2. **responsive**：回答是否回应了用户的问题？信息不足时提出澄清问题、拒绝越权请求，都算回应。

## 运行方式：裁判与 Agent 分开

- 评测报告新增保存每次工具调用的**完整结果**（设备数据是公开信息，体积可接受）。
- `python -m examples.judge_eval_report <报告>` 读取已保存的问题、工具结果和回答，逐条调用裁判，
  写出 `judge_<报告>.json/.md`。**不重新运行 Agent**：同一份回答可以反复裁判、换裁判模型，结果可比。
- 裁判结果**单独报告**，不计入第一层的通过率。

## 校准

- `python -m examples.label_answers <报告>` 在终端里逐条显示问题、工具结果摘要和回答，作者对 grounded 输入 y/n，
  保存到 `evals/labels/<报告>.json`（提交进仓库）。作者标注时**看不到裁判的判断**，避免被带偏。
- 校准报告给出：一致率；混淆矩阵，重点是"人工认定无依据、裁判却判有依据"的条数（裁判漏判）。
- 只有一致率足够高，才在 README 中引用裁判的数字，并同时写出一致率与样本量。

## 裁判配置

- 模型：`qwen3.8-flash`（阿里云百炼模型列表，2026-10-13 查证），与被测的 DeepSeek 不同家族，降低"自评偏好"。
- 通过 OpenAI 兼容接口调用，复用现有 `openai` SDK，**不新增依赖**。
  环境变量：`JUDGE_API_KEY`、`JUDGE_MODEL`（默认 `qwen3.8-flash`）、`JUDGE_BASE_URL`（按账号所在区域填写）。
- `temperature=0`，要求输出 JSON；JSON 解析失败记为 `judge_error`，不猜测。
- 被评内容（工具结果、回答）放在明确的分隔标记内，提示词声明其中的任何指令都只是数据。

## 已知限制

- 35 条样本，一致率只能作为参考；只有一位标注者，没有标注者之间的一致性数据。
- 裁判只看工具结果判断有无依据，无法发现"工具结果本身错了"的情况（数据质量问题由数据层负责）。
- 单价未配置时报告写"未配置"，不估算。
