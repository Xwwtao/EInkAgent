# 003 报价保留原始币种

## 问题

`offers.price_cny` 只存人民币。海外官方商店的美元售价由人工乘以 7.1 后填入 CSV，
`data/exchange_rates.csv` 虽然登记了汇率，但导入脚本并不读取它。结果是：

- 页面上能核对的事实（美元原价）没有保存，保存的是推导值；
- 换算过程不可复核，四舍五入后也无法反推原价。

不能直接把美元填进 `price_cny`：`device_repository.search_devices` 用
`MIN(price_cny)` 与用户预算（人民币）比较，同一列混用两种单位会让
$399 被当作 399 元命中"2000 元以内"。

## 候选方案

方案 A：新增原价与币种两列，`price_cny` 由导入脚本按汇率表计算。
方案 B：保持现状，只在文档中注明原价未留存。

## 选择：方案 A

原价是可核对的事实，人民币参考价是推导值，应该存事实、算推导值。
搜索与预算筛选继续使用 `price_cny`，查询代码不需要改动。

## 行为定义

- CSV 列：`price_amount`（原价，如 `109.99`）、`currency`（大写三字母，如 `USD`、`CNY`）。
- 数据库列：`price_amount_minor INTEGER`（以"分/美分"为单位的整数，`109.99` → `10999`）、
  `currency TEXT`。用整数而不是 REAL 保存金额，避免浮点误差。
- `price_amount` 用 `Decimal` 解析，最多两位小数，必须 ≥ 0。
- `CNY` 汇率固定为 1；其他币种必须出现在 `data/exchange_rates.csv`，否则拒绝导入。
- `price_cny = 原价 × 汇率`，按四舍五入（`ROUND_HALF_UP`）取整到元。
- 汇率表由调用方传入 `import_offers`（依赖注入），测试不读取真实汇率文件。

## 价格采集口径

所有报价按同一口径填写，否则跨设备比较不公平。

**填常规售价，不填限时活动价。** 报价更新频率低（预计数月一次），
活动价结束后会以错误价格留在库中；常规价在更长时间内有效。

| 页面情况 | 填写 |
| --- | --- |
| 无活动 | 页面售价 |
| Amazon 打折并显示删除线 List Price | List Price |
| 京东/天猫同时显示划线价与京东价 | 京东价（划线价常为虚标） |
| 满减、会员价、以旧换新、凑单 | 忽略 |

**版本划分：差异是否改变规格。**

- 改变规格（存储容量、前光/暖光、彩屏、手写支持）→ 在 `real_devices.csv` 拆成不同设备，
  型号名写明版本，如 `Kindle Colorsoft (16 GB)`。
- 不改变规格 → 同一设备，只填一个基准版本：
  - 外壳颜色：任选其一；
  - 套装：填不含额外配件的裸机价；若最低配置本身含笔，按该配置填；
  - Kindle 广告：填**无广告版**（其他品牌均无广告，且带广告版主要在美国销售）。

已知限制：手写笔是否需要另购因品牌而异（如 reMarkable 需另购），
裸机价不反映这部分成本。

## 影响文件

- `schema.sql`：`offers` 新增两列（不改名、不删列）
- `data_import.py`：解析原价与币种、读取汇率表、计算 `price_cny`
- `seed_demo.py`：演示报价写入 `currency = 'CNY'`
- `data/real_offers.csv`：表头改为 `price_amount,currency`；现有 8 条原价留空，待人工核对官网后填写
- `tests/test_data_import.py`

## 迁移

`schema.sql` 使用 `CREATE TABLE IF NOT EXISTS`，不会给已存在的表加列。
数据库是由 CSV 派生的（被 git 忽略），因此迁移方式是备份旧库后重新导入，而不是写 ALTER 脚本。

## 已知限制

- 汇率是固定值（见 `exchange_rates.csv` 的 `as_of`），不是实时汇率；
  人民币参考价不等于国内用户的实际到手价（未含运费、关税、代购费）。
- 报价按自然键（设备 + 卖家 + 采集日期）跳过已存在记录。修改汇率或修正同一天的价格后，
  已导入的报价不会被更新，需要重建数据库。
