# EInkAgent

![Tests](https://github.com/Xwwtao/EInkAgent/actions/workflows/tests.yml/badge.svg)

An AI agent that helps people choose an E Ink reader or note-taking tablet.
You describe what you need in plain language; the agent queries a database
of real devices and price snapshots, compares candidates, and shows where
every price came from.

- **Data**: 49 real devices and 41 price snapshots, each with a source URL
  and collection date (`data/data_quality_report.md`, generated by
  `python data_quality.py`).
- **Agent**: DeepSeek tool calling over three read-only tools, with
  structured error recovery and rule-based answer checks.
- **Interface**: a single-page chat UI served by FastAPI.

## Quick start

Requires Python 3.14 and a DeepSeek API key. A fresh clone through the test
run takes well under a minute on a machine with a warm pip cache.

```bash
git clone https://github.com/Xwwtao/EInkAgent.git
cd EInkAgent
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python data_import.py
python -m pytest -q
```

`data_import.py` builds `data/eink_devices.db` from the CSV files in `data/`.
Running it again does not create duplicates.

Start the server in a terminal where the key is set (zsh):

```bash
read -s "DEEPSEEK_API_KEY?DeepSeek API key: "
export DEEPSEEK_API_KEY
python -m uvicorn eink_agent.api:app --reload
```

Open http://127.0.0.1:8000. Without a key the page still loads, and
`POST /agent` answers HTTP 503 with a message saying the key is missing.
Environment variables are listed in `.env.example`; the app reads the
environment only and does not load `.env` files.

### Try it

| Input | What the agent does |
| --- | --- |
| 预算2000元以内，要能手写，推荐几款 | `search_devices` with a price cap and stylus filter, then details for each match |
| 比较一下 Kindle Paperwhite 2026 和 Kobo Clara BW | Finds both devices by name, then calls `compare_devices` |
| 第二款防水吗？ (as a follow-up) | Uses the previous turns as context |
| 帮我下单 Kindle Colorsoft | Calls no tool and explains it cannot place orders |
| 我想买个阅读器 | Asks about budget, size and use before searching |

Each answer can expand a timeline of the tool calls it made, with arguments,
result counts and failures.

## What it can do

- **Search** by price, screen size, weight, colour, stylus support, open
  system, category, brand, or product name (`keyword` matches every word
  against brand and model).
- **Inspect and compare** up to five devices.
- **Cite prices**: every price comes with the seller, collection date and
  link of the cheapest available offer. Overseas prices are stored in USD and
  converted at the fixed rate in `data/exchange_rates.csv`.
- **Hold a short conversation**: the page sends the last 10 messages with
  each request; the server stores nothing.
- **Recover from tool failures**: invalid JSON, unknown tools, invalid
  arguments and tool exceptions are returned to the model as structured
  errors (never exception text). Two consecutive failures, an empty answer,
  or running out of rounds return a fixed apology instead of an HTTP 500.
- **Check answers without a model**: an answer claiming an order, payment or
  edit is rewritten once and then blocked; an answer exposing internal field
  names such as `is_open_system` is rewritten once.

## Known limitations

- **Data is a snapshot.** Specs were verified on 2026-09-11 or 2026-10-05,
  prices collected on 2026-10-05 or 2026-10-10. Nothing refreshes them.
- **Chinese-brand specs come from IT之家 articles**, because the official
  sites are image-based. The 2026 Kindles come from Amazon product pages;
  older Kindles come from Amazon press releases, with some fields taken from
  Wikipedia and marked in the `notes` column.
  Values were collected from manufacturer, retail and media pages, plus the
  author's own checks where vendors do not publish a field. Fields that could
  not be determined are stored as NULL and reported as unknown,
  so filters such as "no stylus" do not match devices whose stylus support
  is unpublished.
- **Converted prices are references**, not what a buyer in China pays after
  shipping and import fees.
- **The answer checks are keyword rules.** They miss paraphrases, and a
  refusal word in the same sentence hides a claim (for example "我无法处理
  退款，但已帮您下单了"). See `docs/learning/01-agent-walkthrough.md`.
- **No accuracy figure is published yet.** The 20 cases in
  `evals/agent_cases.json` were written for the old fictional data and only
  check which tool and arguments were chosen. Their run reports were not
  committed, so earlier results cannot be verified. A new evaluation with
  committed reports is the next milestone (P2).
- Conversations are lost when the page is refreshed.
- The agent cannot buy anything or change data; all tools are read-only.

## Architecture

```text
Browser (static/index.html) ──POST /agent──▶ api.py ──▶ agent.py ──▶ agent_tools.py
                                               │            │              │
                                    dependency-injected   answer_guard.py  ▼
                                      DeepSeek client                device_repository.py
                                                                            │
                         data/*.csv ──▶ data_import.py ──▶ SQLite (devices, offers)
```

| File | Responsibility |
| --- | --- |
| `eink_agent/api.py` | HTTP endpoints, request validation, model error → status code |
| `eink_agent/agent.py` | Model–tool loop, failure handling, rewrites |
| `eink_agent/answer_guard.py` | Rule-based checks on the final answer |
| `eink_agent/agent_tools.py` | Tool schemas shown to the model, allowlist, argument validation |
| `device_repository.py` | SQL for search, detail and comparison |
| `data_import.py` / `data_quality.py` | Validated, idempotent CSV import and the data report |

Design decisions, each with the rejected alternative, are in
`docs/decisions/`. A guided code walkthrough is in `docs/learning/`.

## HTTP API

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Chat interface |
| `POST` | `/agent` | `{"message": str, "history": [{"role", "content"}]}` → answer, status, tool calls, latency |
| `GET` | `/devices` | Search with `brand`, `max_price`, `limit` |
| `GET` | `/devices/{id}` | One device |
| `POST` | `/devices/compare` | Two to five device IDs |
| `GET` | `/health` | Liveness check |

Interactive documentation: http://127.0.0.1:8000/docs

`POST /agent` status codes: 422 invalid request, 503 no API key configured,
504 model timeout, 502 other model API errors.

## Development

```bash
python -m pytest -q
```

Tests run offline: the model client is replaced with a scripted fake and
each test gets a temporary database seeded with three fictional devices.

To try the agent against DeepSeek from the command line and save the runs to
`evals/smoke_runs/` (ignored by Git):

```bash
python -m examples.smoke_test_agent
```
